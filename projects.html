File 01

Cause-of-Claim Classifier

NLPMachine LearningData Engineering

Insurance claims were recorded as inconsistent free text, making them difficult to analyse consistently.

What I did

  • Built a hierarchical Random Forest + TF-IDF classifier to map free-text claims onto a structured medical taxonomy.
  • Improved accuracy from 37% → 95% through better text preprocessing, without changing the model.
  • Designed the system to flag uncertain cases for human review rather than guessing.
  • Implemented into the production data pipeline, automatically classifying 90%+ of claims.

What I took from it

Good data preparation can matter more than model sophistication. This project also gave me my first hands-on experience building an NLP system from scratch.

File 02

Underwriting Normalisation

Data EngineeringClusteringRisk ModellingLLMs

Underwriting data contained over 500,000 unique free-text question–answer pairs, making it difficult to use for downstream analysis.

What I did

  • Built a pipeline using text embeddings and K-means to transform messy responses into 9 interpretable risk markers.
  • Validated the markers through statistical analysis and predictive modelling, with a decision-tree model achieving 0.977 AUC.
  • Worked with underwriting guidelines and medical literature to refine the taxonomy.
  • Contributed to the process of introducing LLM automation, considering data privacy, prompt injection, version control and governance.

What I took from it

I enjoyed this project because it combined technical work with judgement — the model was only one part of the solution.

File 03

Studying Condition Comorbidity

Data AnalysisSurvival ModellingHealthcare

How do lifestyle factors and combinations of health conditions affect mortality?

Working with 1+ billion rows of UK GP records, I built and structured analysis datasets before investigating how conditions interacted with one another.

What I did

  • Cleaned and transformed longitudinal healthcare data, handling missingness, inconsistent inputs and observation periods.
  • Investigated interactions between conditions and lifestyle factors using XGBoost, SHAP and ultimately Cox survival modelling.
  • Explored unexpected results through further analysis and existing medical research rather than assuming the model was wrong.
  • Presented findings and conclusions to the wider team as part of the company's work towards entering the annuities market.

What I took from it

Data science rarely gives you a single “correct” answer. Good analysis is about building enough evidence to make a well-informed decision.

File 04

AI Data Schema Agent

AIPythonData Documentation

People across the company frequently needed help navigating complex datasets, creating a constant stream of ad-hoc questions.

I built an AI-powered data schema assistant that could explain tables and fields, identify where information was stored, and even generate SQL for questions such as:

“What is the sum assured split by product and gender?”

I automated the documentation of 12 large datasets, including field definitions, data types, ranges and row counts, before connecting the documentation to Microsoft Copilot.

What I took from it

I enjoy building small tools that remove repetitive work and make data more accessible to others.
